**Finding F1 — high — M3 D7, lines 146 and 291–307; risk 7, line 489; PR3a, line 436.** The proposed logical header scopes and per-account first-use authentication do not isolate Git's own retained pack state. The design needs a deciding packed-store probe and an explicit resolution before promising unchanged availability refusals on one shared child.

The committed foreground driver `audit/m3-design-r1/packed_store_probe.py` constructs a raw-index fixture containing `file` with `b"payload\n"`, packs reachable objects with `git repack -ad`, and removes loose duplicates with `git prune-packed`. It selects and enters two snapshots before either subject's payload work, reads through A, removes the three pack-related files, clears A's entire Python `_headers` dictionary, and requests the same object through A and then the still-cold B. The results are:

```text
warm_transport_cold_python_headers: value "payload\n"
independent_entered_cold_transport: receipt.snapshot.SnapshotError
object c2981a9931b383b5eb128dc5e3505654ab5269b6 is unavailable
different_pids: true
```

This directly tests the transport substitution proposed in M3. It does not claim that unimplemented context code was run. A's post-removal call executes a new `info` request because the Python header cache was cleared, followed by `contents` and payload hashing (`snapshot.py:1215–1287`). B's first `entry` reaches the same OID and refuses at `_parse_header` (`snapshot.py:1194–1197,2453–2472`). Thus adding account membership and replaying Python charges cannot by itself preserve the result. Git retains process-local object-store state beneath those mechanisms. The authenticated payload remains correct; the observable availability refusal changes.

D7 already names object deletion as a future gate, which is good, but the proposed mechanism does not resolve the gate's counterexample. Add packed as well as loose objects, warm/cold reader permutations, pack replacement/removal, and unchanged-store controls to PR1. Specify whether exact legacy availability is required and how it is achieved, or name context-scoped availability as another deliberate, maintainer-approved correction. Do not silently waive it as cache deduplication, or claim that a second `consume` recreates a cold process. Treat this as a compatibility feasibility gate before the ownership implementation, alongside the independent-owner conflict.
