# 0.7 M1: one protected-tree policy

Design record, 2026-09-06. This is a design-only lane: no source or test changes.
The baseline is `e404d59298c972993b268494c726472a2613f3b3` on
`design/0.7-m1-protected-tree-policy`; `git diff v0.6.0 -- src tests CONTRIBUTING.md`
is empty. Source and test line numbers below refer to that baseline; package
source paths are relative to `src/receipt/`, and `test_*.py` references are
relative to `tests/` unless a consumer repository is named. Issue #62 was read
from the supplied `issue-62.md`; its scope and `CONTRIBUTING.md` govern this record.

The decision is one owner of tree-policy facts, with explicit obligations for
each use of the tree and compatibility renderers at existing call boundaries.
A shared view must include tree nodes, empty trees and actual ancestor listings.
It must preserve both the declared repertoire and the stricter requirements of
writing names onto a host filesystem. It must not confuse a raw-object binding
claim with a checkout or a caller-owned directory claim.

The census below records the baseline; executed probes, the proposed design,
migration steps and ranked risks follow it.

## Census conventions

`E` means an assertion of the entire exception/failure string, `S` a substring or
regex marker, and `V` verdict/order coverage. Tests that assert only a marker do
not pin the rest of the text. Where no exact pin was found, that is a migration
test gap, not permission to change the message. Adjacent Python string literals
in tables/code concatenate exactly as in source. Exception classes and wrapper
prefixes are part of compatibility. Git transport/authentication and actual
filesystem read guards are included to establish the boundary of what M1 moves.

## Directory/materialized readers that must not disappear

These sites implement the existing public read-once directory contract. They bind OS identities/spelling and protect the private materialization after write. They are not redundant Git-object authentication checks: removing them because a Git view is accepted changes the concurrent-writer/read-once safety contract. They have no `_names.py` repertoire, sibling-fold or DOS rules, and no `.gitattributes` evaluation. A directory adapter can use shared policy for known facts while retaining descriptor/lstat checks and historical strings. Public `verify_release_chain` must not suddenly require a Git repository.

## Scope and terminology

There is NO runtime directory adapter in corpus.py at this revision. `verify_corpus_binding` requires a selected `TreeSnapshot` (`corpus.py:1758–1762`); `tests/test_corpus.py:165–178` is a TEST-ONLY convenience adapter that commits a supplied directory then selects its commit. Comments referring to an old `os.lstat`, filesystem sweep, or `_DirectoryGenerations` are historical, not live screens. Direct-directory release-chain screens are in the directory-reader census above.

`_quoted(value)` at `corpus.py:539–561` is not equivalent to unrestricted `repr`: it computes `text = repr(value)` and, above `MAX_QUOTED_TEXT`, returns `f"{text[:MAX_QUOTED_TEXT]}…[{len(text) - MAX_QUOTED_TEXT} more characters]"`. Preserve that renderer when moving decisions. Both declared repertoires use ASCII folding only, never Unicode casefold or normalization; legacy corpus refusal words still say “normalization-insensitive”. Retain the words without reintroducing the old algorithm.

## Proposed module and protected view

Add `receipt.protected_tree` as the sole owner of *which tree policy applies to
which use*, how its facts are computed, and how bounded findings are selected.
Reuse the grammar/fold/8.3 primitives in `_names.py`; move attribute-policy
parsing and matching out of `snapshot.py` behind forwarding functions. Keeping
primitive operations and authenticated object I/O in separate modules does not
create another policy owner. No verifier may independently reimplement a name,
mode, ancestor, suffix-alias or attribute decision.

The proposed module surface below is for package callers. This design does not
introduce public refusal codes, remove existing APIs, replace the executable
spec, or start M3's repository-context redesign. Finding variants are typed
internal records, extensible without a closed public enum.

| Surface | Contract |
|---|---|
| `ProtectionPlan` | Frozen, normalized obligations derived from existing specs: repertoire; ordered selected prefixes and configured alias targets; actual ancestor-listing scope; whole-tree name scope; content roots and suffixes; exact required state/attested paths; export prefixes; attribute target selectors; anchor origin. | `TreePolicy(snapshot, *, policy_version, work)` | Verification-local evaluator over an entered, authenticated `TreeSnapshot`. A `Finding` holds the condition and its witness: exact/raw path, parent, local
name(s), full diagnostic descendant when needed, expected configured spelling,
mode/object type, suffix pin, attribute source path/line/name and exact/folded
reading, or budget kind/ceiling. It also retains stable traversal/rule ordinals.

`repr`, absolute paths, the legacy “index”, “base” and
“normalization-insensitive” words, wrapper prefixes and exception classes stay

The subject key includes snapshot/session provenance, object format, selected

## Evaluation order and compatibility

Policy evaluation has a dependency order, rather than a universal first thrown
exception. The reader authenticates raw objects, canonical tree order, legal raw
modes, names and structural budgets first. For each requested stage, the policy
then computes component grammar/repertoire/export eligibility and fold keys;
classifies object types, leaf modes and ancestor shapes; derives sibling and
configured-prefix aliases plus scoped DOS suffix findings; and, only when the
stage requires it, reads/parses/evaluates attributes. Both exact and ASCII-folded
attribute readings remain independent and a transform under either refuses.
Repository settings, worktree/global/info attributes, filters and Git checkout
semantics are not attribute-policy inputs. Reader selection may still reject an
invalid repository setting, as it does today.

“Once” means at most one evaluation of a fact for an immutable subject and
obligation, with shared indexes reused across stages. It does not mean throwing
one whole-tree exception at entry. A single eager global error is incompatible
with the pinned texts and phase outcomes. Even computing attributes early and
saving the exception is unsafe: it can consume budget, abandon a poisoned
snapshot, or perform object I/O before an earlier materialization failure.
Attribute evaluation therefore starts lazily at its existing barrier. The same
rule applies to later binding obligations: do not perform binding-only folds or
parse binding-only inputs before their legacy prerequisites succeed.

Explicit schedules preserve observable precedence:

| Boundary | Selection/raising schedule retained |
|---|---|
| Composed verify | Optional history first; configured aliases, scoped names, sibling merges, release DOS suffixes; state lookup/modes and payload bounds; all export modes, then export names/siblings; actual materialization and its I/O guards; attributes; anchor/chain checks; binding journal/schema/declaration-alias prerequisites then binding tree obligations. Finalization auditing remains last and may invalidate prior passes. |
| Base chain | Scoped name/alias schedule; materializer mode-before-name order; physical materialization; attributes; anchors/chain. Caller-provided anchor exclusions are part of the plan. |
| Append | State shapes; protected ancestors; configured aliases, scoped repertoire/siblings and DOS suffixes with complete-path foldability; attributes; surface classification and gate-only return; retained row/history/pre-genesis/manifest checks and push materialization. State/base mode equality remains at its current later position. |
| Binding | Parse journal; declared whole-path aliases; declared prefix aliases/budgets; all tree names before all sibling collisions; content-root aliases; each root's existence/mode then descendants in existing sorted order: gitlink, suffix/DOS, selected-leaf mode; closed world/tombstones/attested checks and digests. |
| Standalone snapshot APIs | Keep public argument/provenance checks, object-type-before-mode for payloads, mode-before-name for materialization, and their narrower alias/attribute contracts. No implicit attribute check is added to materialize. |

This order is represented as data/selection logic over findings, not a second
set of name or mode algorithms in the verifiers. When a condition needs a
later-stage fact, that stage evaluates it once before selection. Early failure
stops work at the old barrier. The API refuses use of incomplete selections, so
an unset attribute outcome cannot accidentally mean “clean”.

The module owns name/fold/index and attribute-policy admission, parsing,
matching and cache limits. The budget census gives every current ceiling and
message. Keep structural Git-object limits at the reader, actual streamed byte
and write charges at their owners, and declaration parsing limits in corpus;
move only shared declaration-fold/index accounting into the policy. State,
content and materialization payload ceilings do not become optional because a
name view exists. M1 uses the existing `_link_verification_work` relationship;
one repository context is M3 and remains out of scope.

The repeat-charge probe rules out silently equating cached work with admitted
work. Retain a compact legacy charge schedule per ordered API use: input counts
and supplied path bytes are charged before deduplication as today, attribute
source loads follow the same cache semantics, and cached match outcomes carry
work-cost checkpoints sufficient to replay budget exhaustion at the same path,
rule and reading. These are arithmetic admission charges, not re-execution of
policy. The actual evaluator remains bounded by the same ceilings; the logical
compatibility ledger controls acceptance. Keep checkpoints compact and stop at
the first refusal rather than storing one object per matching step. Preserve
existing `SnapshotWork` fields, constants and monkeypatch seams used by tests;
forwarding must consult the legacy limit at call time, not copy it once at import.

Do not invent a new lower policy-work or cache ceiling in M1. Use existing tree,
path, prefix, rule and work limits to bound indexes; constrain growth to bounded
entries/components/rules with compact first witnesses and cached folded keys.
If implementation needs a new ceiling, demonstrate its boundary and document
the newly refused input before accepting it; that is a scope/behavior change.
The charge-schedule proposal needs the boundary tests below before migration,
especially overlapping attributes across base/candidate and resumed stages.
