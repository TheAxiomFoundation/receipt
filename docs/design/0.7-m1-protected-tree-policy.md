# 0.7 M1: one protected-tree policy

Design record, 2026-09-06. This is a design-only lane: no source or test changes.
The baseline is `e404d59298c972993b268494c726472a2613f3b3` on
`design/0.7-m1-protected-tree-policy`; `git diff v0.6.0 -- src tests CONTRIBUTING.md`
is empty. Source and test line numbers below refer to that baseline; package
source paths are relative to `src/receipt/`, and `test_*.py` references are
relative to `tests/` unless a consumer repository is named. Issue #62 was read
from the supplied `issue-62.md`; its scope and `CONTRIBUTING.md` govern this record.

The decision is one owner of tree-policy facts, with explicit obligations for
each use of the tree and compatibility renderers at existing call boundaries.
A shared view must include tree nodes, empty trees and actual ancestor listings.
It must preserve both the declared repertoire and the stricter requirements of
writing names onto a host filesystem. It must not confuse a raw-object binding
claim with a checkout or a caller-owned directory claim.

The present record first inventories the baseline; design, executed probes,
migration steps and risks follow the census in the completed revision.

## Census conventions

`E` means an assertion of the entire exception/failure string, `S` a substring or
regex marker, and `V` verdict/order coverage. Tests that assert only a marker do
not pin the rest of the text. Where no exact pin was found, that is a migration
test gap, not permission to change the message. Adjacent Python string literals
in tables/code concatenate exactly as in source. Exception classes and wrapper
prefixes are part of compatibility. Git transport/authentication and actual
filesystem read guards are included to establish the boundary of what M1 moves.

## Directory/materialized readers that must not disappear

These sites implement the existing public read-once directory contract. They bind OS identities/spelling and protect the private materialization after write. They are not redundant Git-object authentication checks: removing them because a Git view is accepted changes the concurrent-writer/read-once safety contract. They have no `_names.py` repertoire, sibling-fold or DOS rules, and no `.gitattributes` evaluation. A directory adapter can use shared policy for known facts while retaining descriptor/lstat checks and historical strings. Public `verify_release_chain` must not suddenly require a Git repository.

## Scope and terminology

There is NO runtime directory adapter in corpus.py at this revision. `verify_corpus_binding` requires a selected `TreeSnapshot` (`corpus.py:1758–1762`); `tests/test_corpus.py:165–178` is a TEST-ONLY convenience adapter that commits a supplied directory then selects its commit. Comments referring to an old `os.lstat`, filesystem sweep, or `_DirectoryGenerations` are historical, not live screens. Direct-directory release-chain screens are in release_chain.py (other agent's census).

`_quoted(value)` at `corpus.py:539–561` is not equivalent to unrestricted `repr`: it computes `text = repr(value)` and, above `MAX_QUOTED_TEXT`, returns `f"{text[:MAX_QUOTED_TEXT]}…[{len(text) - MAX_QUOTED_TEXT} more characters]"`. Preserve that renderer when moving decisions. Both declared repertoires use ASCII folding only, never Unicode casefold or normalization; legacy corpus refusal words still say “normalization-insensitive”. Retain the words without reintroducing the old algorithm.
